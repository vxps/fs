# FitSpot — сервис подбора тренировок по теннису и паделу

> Магистерская ВКР «Стартап как диплом», ИТМО  
> Автор: Максимович К.

## О проекте

FitSpot — веб-сервис для любителей тенниса и падела в Москве. Платформа агрегирует предложения «тренер + корт + свободное время + цена» и позволяет игроку подобрать и забронировать тренировку в несколько кликов.

**Проблема:** игрок тратит время на поиск тренера, сверку расписания корта и согласование — информация разрозненна между сайтами клубов, мессенджерами и соцсетями.

**Решение:** единый каталог с фильтрами по спорту, району, дате и цене. Игрок видит итоговую стоимость (тренер + аренда корта), выбирает слот и создаёт бронь.

## Реализованная функциональность

- **Регистрация и авторизация** с ролями «игрок», «тренер», «администратор»; JWT-токены.
- **Обязательная анкета игрока** (спорт, уровень, район, время, приоритет, цель) — без неё сервис недоступен.
- **Каталог 100 демонстрационных кортов** — 10 клубов × 10 кортов (60 теннис + 40 падел), расписания на 14 дней.
- **Лента предложений** «тренер + корт + слот»: фильтры по спорту, району, дате, времени суток; сортировка по стоимости, рейтингу, времени, цене корта.
- **Бронирование**: выбор слота → предварительная запись → подтверждение корта (игроком или тренером, в зависимости от клуба).
- **Жизненный цикл записи**: `awaiting_court → confirmed → completed / no_show / cancelled`. Отмена освобождает слот тренера и окно корта.
- **Кабинет тренера**: анкета с верификацией, открытие и повтор окон, управление заявками.
- **Модерация**: администратор одобряет профиль нового тренера.
- **Адаптивный дизайн** без стоковых фотографий.

### Что пока не реализовано

Реальная оплата (холд / возврат / комиссия), SMS / Telegram-уведомления, интеграция с CRM клубов (yClients API), групповые тренировки, A/B-эксперименты H2–H3. Текущее ранжирование — детерминированное демонстрационное.

## Локальный запуск

### Требования

- Python 3.11+
- Node.js 22+

### Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

API-документация: http://127.0.0.1:8000/docs

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Приложение: http://127.0.0.1:5173/

### База данных

SQLite создаётся автоматически при первом запуске (`backend/fitspot.db`). Для PostgreSQL — задайте `DATABASE_URL` в `backend/.env` (см. `.env.example`).

## Эксперимент H1 — конкурентное бронирование

Папка `experiments/h1-concurrent-booking/` содержит артефакты проверки гипотезы H1: *«Паттерн preclaim (короткая блокировка + внешняя оплата + подтверждение) устраняет неопределённые состояния при параллельных бронированиях»*.

**Метод:**
- PostgreSQL с ограничением `EXCLUDE USING gist` на пересечение временных интервалов.
- Два контура: `control` (оплата внутри транзакции) и `preclaim` (claim → оплата вне транзакции → confirm).
- Сетка параметров 5×5: уровни конкуренции C ∈ {1, 2, 5, 10, 25} × задержка оплаты D ∈ {0, 100, 500, 1000, 2000} мс.
- 20 раундов на каждую комбинацию → 8 600 измерений.

**Результат:** preclaim — 0 `unsafe_abort` по всей сетке (4 300 попыток); control — ~10% при C ≥ 2. Разность статистически значима (Fisher exact test, p < 10⁻⁵ для C ≥ 2).

Подробности: [`experiments/h1/analysis.txt`](experiments/h1/analysis.txt)
